# 信息源与可信度

## 采集源

| 源 | 角色 | 说明 |
|---|---|---|
| ai-news-radar | 主雷达 | GitHub Actions 每 30 分钟–4 小时更新；24h 约 200 条，含官方/媒体/X 聚簇事件 |
| AI HOT | 中文精选 | 公共 API `https://aihot.virxact.com/api/public/items?mode=selected&limit=50`，需浏览器 UA |
| follow-builders | 观点层 | 26 个 X builder、6 档播客、2 个博客；适合补充观点，不适合当要闻唯一来源 |

| IT之家 / 界面 / 36氪 / ITBear | 可截图媒体 | 官方页不可截时作为证据来源，标注 `媒体报道` |

## 可信度分级

- `官方确认`：URL 属于厂商官方域名，或来自官方 RSS/官方模型卡/官方公告。
- `多源印证`：同一事件 ≥ 2 个来源，或聚簇事件 `source_count ≥ 2`。
- `单源信号`：只有 1 个来源，尤其是 X/微博/公众号。可进候选池，但不进「要闻」推荐。

## 过滤规则（已在 collect_daily.py 内置）

- 周报/日报/周刊/速递/早报/newsletter/digest/roundup 降权并排除出推荐。
- `详解/手把手/教程/观点/复盘/解读/如何/指南/玩法/实测` 视为观点文，排除出推荐。
- `传闻/曝/据称/据悉/可能/计划/或将/未证实` 在非官方来源上降权。
- 同厂家 + 同事件关键词（模型名、IPO、融资、收购）合并为一条。
- 厂家按标题中最早出现的位置判定，避免被摘要里的其它厂家带偏。

## 写稿红线

- 旁白和卡片只能使用截图正文、候选摘要里出现的事实；数字、日期、型号必须能在来源里找到。
- 官方发布与媒体报道分开标注，不把媒体转述写成官方口径。
- 日期用系统时间现取；没有官方发布时要明确说明，不用传闻或旧模型填充。
- 成片条数和时长由内容决定，不设 30 秒上限；不为卡时长删掉重要条目。
